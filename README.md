# 童鞋网售召回退款协同

协同处理已全部网售不合格童鞋的消费者通知、退货和退款。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括童鞋经营者、电商平台、购买家庭、市场监管人员。

资料所依据的领域事实如下：

- 执法案例中的二百八十双童鞋通过电商平台全部售出
- 涉案童鞋经检验为不合格产品
- 案发时商品已经全部下架，无法找回实物
- 下架链接无法回答哪些家庭已经收到、哪些订单转赠他人

资料还规定了召回协同的工作方式：

- 受影响交易识别信号：采购批次、商品变体、订单、物流、收货确认、消费者主动报告
- 分阶段处理：识别受影响交易、分阶段通知、退货、退款，无法追回的逐项注明原因
- 六类不得重复计算的情形：合并订单、拒收重派、匿名购买、售后换货、重复通知、支付回调
- 信息可见性：消费者可核验通知真伪并查看本人处理状态，商家仅获得履约所需信息
- 召回闭环核对：售出 = 已控制 + 未控制，监管人员据此判断召回是否结束

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实、识别信号、去重规则和召回闭环账目，并能核对售出、触达、退回、退款与未控制之间的数量关系。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。
