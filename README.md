# 童鞋网售召回退款协同

协同处理已全部网售不合格童鞋的消费者通知、退货和退款。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括童鞋经营者、电商平台、购买家庭、市场监管人员。

`contracts/reconciliation.schema.json` 规定监管侧闭环报告结构（`python -m src.report` 的输出）。

资料所依据的领域事实如下：

- 执法案例中的二百八十双童鞋通过电商平台全部售出
- 涉案童鞋经检验为不合格产品
- 案发时商品已经全部下架

## 识别链路

商品下架后链接无法找回实物，受影响交易只能沿业务数据逐级还原：

```
采购批次 → 商品变体 → 订单行 → 物流投递 → 收货确认 / 消费者主动报告
```

- 每双鞋以 `批次-变体-序号` 作为唯一实物单元（unit），一双只能挂在一个订单行上，重复挂单直接报错；
- 物流单可挂多个订单号（合并订单），多个订单的同一收货家庭只产生一条通知；
- 拒收重派以物流事件体现，签收家庭不变，重发通知走幂等；
- 转赠后由受赠人主动报告的，通知与退货均指向受赠人；未报告的转赠实物保留为"未控制"并注明去向不明；
- 召回开始前已完成售后换货收回的实物直接计为已控制，不通知、不重复退款；调换给消费者的合格品来自合格批次，不计入 280 双。

## 去重与幂等

| 场景 | 处理 |
| --- | --- |
| 合并订单 | 多订单号共用物流单与收货方，通知、退货单各一张 |
| 拒收重派 | 重复通知返回同一条记录，仅 `attempts` 增加，计数不变 |
| 匿名购买 | 商家不可见身份，仅经平台站内信触达；商家视图无身份字段 |
| 售后换货 | 召回前已收回的实物不进入通知目标，调换品不属受影响批次 |
| 重复通知 | 以（接收方, 实物单元集合）为键幂等 |
| 支付回调重复 | 以回调编号 `callback_id` 去重，重复回调返回丢弃且不二次入账 |

同一实物单元落入第二个处置桶（如已退回又登记退款不退货）会抛出处置冲突。

## 分阶段处置与隐私视图

1. **通知**：按识别链确定接收方，短信或站内信送达；通知带 HMAC 校验码。
2. **核验**：消费者凭通知码加本人订单号即可核验真伪并查看逐双处理状态；码对他人订单无效，不能枚举。
3. **退货**：商家只收到物流令牌、变体与数量（`merchant_view`），不含家庭身份与联系方式。
4. **退款**：支付回调入账后逐双标记；实物无法追回的，先退款再注明原因（如已穿旧丢弃）。
5. **未控制**：无法触达、已触达无回应、转赠后无人报告三类，逐双注明原因。

监管人员视图（`regulator_view`）只给可核对的数量关系，不含家庭明细。

## 闭环关系

监管人员以下列恒等式判断召回是否结束：

```
售出 280 = 已退回 265 + 换货已收回 2 + 退款无法追回实物 2 + 未控制 11
退款单元 ⊆ 已退回 ∪ 退款不退货
通知送达单元 ⊆ 通知目标单元
```

当前合成数据集恒等式全部成立，但存在 11 双注明原因的未控制残余，因此 `can_close=false`；只有残余为零，或监管人员书面接受该残余（`closure_check(regulator_accepts_residual=True)`）后，召回才能结束。

## 合成数据集

`src/sample_data.py` 构造恰好 280 双的假名数据，覆盖合并订单、拒收重派、匿名购买、售后换货、转赠报告、重复通知与重复回调等边界场景；不含真实身份信息。

## 本地校验

```
python -m unittest discover -s tests   # 21 项核对测试
python -m src.report                   # 输出监管闭环报告
python -m src.report --accept          # 模拟监管接受残余后的结案判定
```

仓库不保存账号、密钥、连接串或真实身份信息；通知核验码的签名密钥仅为演示常量。
